# 001 · 计划文档的粒度与书写时机

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-19 |
| 状态 | 生效 |
| 关联 | `AGENTS.md` §2（先想清楚再动手）、§7（文档同步）；`docs/plans/2026-10-19-v0.1-总计划.md` §8 |

## 背景

AGENTS §2 规定：新增/修改 ≥3 个文件、涉及数据结构或公共接口变更、涉及新功能这三类工作，先把 plan 写入 `docs/plans/<日期>-<主题>.md` 再执行。

v0.1 分 M1–M5 五个阶段，每个阶段都满足上述三条。问题变成：**五份阶段计划是现在一次写完，还是各阶段启动时再写？**

## 选项

**A. 现在一次写全五份阶段计划。**
优点是"整条路径提前可见"；缺点是 M3 的拦键状态机取舍要等 spike 实测、M4 的抄写交互要等 M2 定型的 `Lock.vue` 结构，现在写只能写猜测。猜出来的步骤无法判定是否达成，违背 AGENTS 元原则 1（每条约定必须可判定）。且执行时必然偏离，plan 与代码分叉后就没有约束力了。

**B. 只写总计划，阶段计划一律不写。**
省事，但违反 AGENTS §2（阶段执行前必须有含验收标准的 plan），且单个阶段的步骤与验收在总计划的粒度下不可判定。

**C. 总计划一次写全 + 阶段计划在该阶段启动时写。**
总计划承担"不缺项"（阶段顺序、依赖、A-1~A-25 归属、门禁、卡点）；阶段计划承担"可执行"（步骤序列、每步验收、文件清单、偏离登记）。

## 结论

**采纳 C。**

- `docs/plans/2026-10-19-v0.1-总计划.md`：一次写完，只在阶段边界或口径变化时修订。
- `docs/plans/<日期>-M<n>-<主题>.md`：该阶段启动当天写完再动代码，六个固定小节（目标与不做 / 前置 / 步骤序列 / 出口条件 / 偏离登记 / 未验证项），缺一节不算写完。
- 阶段内若有前置 spike（M3 拦键），spike 的五项验收与失败降级路径必须随该阶段计划一起写，不能拖到 spike 当天临时定。
- 阶段结束时原地标 `状态：完成 YYYY-MM-DD`，**不删除、不重写**——偏离记录本身就是 §2 要求的可追溯依据。

## 代价

无法在开工前给出整条链路的细粒度工作量。补偿：总计划给每阶段估时（取自 PRD §16）与依赖图，足够判断"现在能不能开工"。

## 推翻条件

出现以下任一情况，改为"提前一次写全部阶段计划"：

1. 有第二个人并行开发，阶段计划要交给别人执行（对方无法依赖现场的隐性判断）；
2. 阶段需要外包或跨会话交接给不掌握上下文的执行者；
3. 某一阶段反复因"没想到的依赖"返工 ≥2 次——说明提前暴露依赖的价值超过了猜测的成本。
