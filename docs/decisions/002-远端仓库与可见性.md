## 背景

本地 `main` 已有两次提交。需要远端的原因只有两个：**异地备份**（本机硬盘是单点）与**换机续做**。产品本身承诺全程离线、无遥测，因此远端与产品运行无关，纯属开发基础设施。

PRD §18 Q-6 把"是否发布到 GitHub 公开仓库"留到 v1.0 前定。当前不需要公开：v0.1 的分发方式是"解压 zip 给 ≤10 位道友"，不是仓库。

## 选项

**A. 公开仓库。** 好处是省事、可当作品展示；代价是代码与"防绕过设计"（例如 `%APPDATA%` 明文题库、无完整性校验、§13 的已知局限）全部公开，容易被误读成"安全软件"，也可能引来"这锁不住"的无效讨论。且公开即等于承诺维护 issue。

**B. 私有仓库。** 满足备份与续做，不承担任何对外承诺。代价是没有社区反馈，且未来若要公开需一次性处理 LICENSE、README 免责声明、issue 模板。

**C. 先不建远端。** 最省事，但本机硬盘是单点，AGENTS §3 又要求"首次推送前先在 GitHub 建同名空仓库"，拖着等于违反约定。

## 结论

**采纳 B：私有仓库，远端固定 SSH `git@github.com:BigTanDog/biguansim.git`。**

- 不使用 HTTPS：本机 GCM 会弹窗卡住（AGENTS §3 已记）。
- 建仓后立即首推 `main`，之后每个 commit 按常规推送，不做长期分支（trunk-based）。
- **Q-6 仍未决**：私有只是当前可见性状态，不构成"不公开"的承诺。
