# 004 · 拦键状态机结论（M1 spike）

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-20 |
| 状态 | 状态机部分已验证；**系统行为五项待人工实测**（见 §3） |
| 关联 | PRD F-3.3 / F-3.4 / A-3；TDD §4.4、§8.2；M1 计划 S10 |

## 1. 背景

M3 的整个结界方案压在一个前提上：**"放行 `Win+L`"与"拦截 `Win+E`"能否共存**。若不能，A-3 的口径要变、PRD §13 要加一条局限，而这两处都改在产品文档里，越晚发现越贵。因此把验证前移到 M1 末尾。

## 2. 已验证的结论（代码 + 单测）

实现见 `src-tauri/src/platform/keyfilter.rs`，探针见 `src-tauri/examples/hook_probe.rs`。

| # | 结论 | 证据 |
|---|---|---|
| C-1 | 组合键判定可以抽成**纯函数** `decide(vk, is_down, &mut ModState) -> Swallow/Pass`，不需要访问系统状态 | 15 条单测，`cargo test` 全绿 |
| C-2 | `Win` 键**按下必须放行**：吞掉它系统就认为 Win 从未按下，`Win+L` 也就不成立；但**抬起要分情况**（见 C-8） | `win_down_itself_passes`、`win_release_after_win_l_passes` |
| C-3 | `Win` 按住期间吞掉字母与功能键，但放行 `L` | `win_e_is_swallowed`、`win_d_r_i_s_x_are_swallowed` |
| C-4 | 左右 `Win` 必须**分别计数**，否则交替按会串状态、抬不起 | `left_right_win_do_not_share_state` |
| C-5 | `Alt` 期间吞 `Tab`/`Esc`/`F4` 不影响 `AltGr`（= Ctrl+Alt）打特殊字符 | `alt_gr_typing_is_not_broken` |
| C-6 | `Ctrl+Alt+Tab`（持久切换器）与 `Win+Ctrl+←/→`（虚拟桌面）由现有分支天然覆盖 | `ctrl_alt_tab_is_swallowed`、`win_ctrl_arrow_is_swallowed_for_virtual_desktops` |
| C-7 | 音量键、普通打字、输入法切换（`Ctrl+Space`、`Shift`）全部走"无命中 → 放行"分支 | `plain_keys_and_volume_pass_through`、`ime_switch_keys_pass_through` |
| C-8 | **单击 `Win` 的抬起必须吞掉**，否则开始菜单弹出并露出任务栏（SP-4 实测）。判据：整段按住期间没按过别的键就吞抬起，按过则放行 | `single_win_release_is_swallowed`、`win_release_after_other_key_passes` |
| C-9 | 低级钩子会同时上报**通用**与**左右专用**修饰键 VK（`VK_LCONTROL 0xA2` 等），只认通用 VK 会让 `Alt+Tab`、`Ctrl+Shift+Esc` 与探针安全退出组合键全部失效 | `side_specific_modifier_vks_are_recognised` |

**对 M3 的直接价值**：TDD §8.2 里"组合键状态机只能手工"的范围缩小到**只剩系统行为那一层**——钩子是否真的吞掉了按键、系统是否仍认为 Win 被按住。策略逻辑本身进了单测。

## 3. 实测结果（2026-10-20，你本机跑探针）

运行方式（分钟数是自动退出上限，可省略，默认 5）：

```
cargo run --manifest-path src-tauri/Cargo.toml --example hook_probe -- 1
```

| # | 操作 | 结果 |
|---|---|---|
| SP-1 | `Win+L` | 通过 |
| SP-2 | `Win+E` | 通过（不弹资源管理器） |
| SP-3 | `Alt+Tab` | 通过（不切应用） |
| SP-4 | 单按 `Win` | **未通过**：开始菜单照常弹出，露出下方任务栏；点任务栏能切软件吗——实测"点了没跳转"（被置顶窗口压住） |
| SP-5 | 打字 / 输入法 / 音量 | 通过（打字无影响） |

**探针本身的两个缺陷（已修，需复测）**：

1. 安全退出 `Ctrl+Alt+Shift+Q` 不生效——根因不是钩子吞键，而是状态机只认通用修饰键 VK（`VK_CONTROL`），而钩子实际会上报左右专用 VK（`VK_LCONTROL 0xA2`）。见 §2 的 C-9。
2. 自动退出写成固定 5 分钟且不可配，实测时被迫等 15 分钟。现已支持命令行分钟数。

## 4. 决策

1. **M3 直接复用 `keyfilter::decide`**，不另写第二份实现；钩子层只负责"取 vk + 判上下 + 调用"。
2. **SP-4 的修法**：`Win` 按下仍放行（否则 `Win+L` 失效），**抬起按"整段按住期间是否按过别的键"分情况**——没按过就吞掉抬起（抑制开始菜单），按过就放行。已实现并有 3 条单测；**但"吞掉抬起会不会让系统以为 Win 一直被按住"必须复测**（SP-5 里连打一段字即可验证）。
3. **仍不通过** → 降级到最小集合（`Alt+Tab` / `Ctrl+Esc` / `Ctrl+Shift+Esc` / `Alt+F4`），把 `Win` 组合键写进 PRD §13 已知局限并收窄 A-3。**这一步需要你拍板，我不自行改产品口径。**
4. 即便 `Win` 组合键全部到位，**任务栏本身仍可能被点到**（SP-4 里"点了没跳转"说明覆盖住了，但这依赖置顶生效）。M3 若发现某机型压不住，按 PRD §13-8 如实记录。

## 5. 推翻条件

- 实测发现"放行 Win 按下 + 吞 Win+E"在某些输入法/键盘驱动下必然弹出开始菜单 → 降级方案生效，本结论作废；
- M3 引入抢焦点后，若抢焦点本身已足够阻止切桌面，可重新评估是否值得为 Win 组合键承担误伤风险。
