## 1. 目标与不做什么

**目标**：把 M1 的"能锁能出"补成一条完整流程——**起势 3-2-1 → 闭关 → 到点钟鸣 → 结算页 → 再入一关**，并让「再入一关」预填上次时长。M2 结束时 A-1 全流程应能连跑 5 次不出错。

**不做（M3 起）**：键盘钩子与抢焦点、亮度、显示变化、电源阻止睡眠；以及在 M4/M5 的冷却/答题/抄写/统计/题库。

**本阶段必须诚实的两处**（PRD 原则 3）：

1. 起势 3 秒内的 Esc 取消**只监听窗口按键**，没有全局钩子——Alt+Tab 切走后按 Esc 无效。这是 M3 才解决的，README 与起势界面都要写清楚。
2. 钟鸣是**前端 Web Audio 合成**，不走音频文件；系统静音时听不到，静音检测（F-7.3）按 D-13 延后到 M5。

## 3. 步骤序列

### S1 `Arming` 状态机（0.5 d）

产出：`core/session.rs` 扩展为 `Idle / Arming / Locked / Settled` 四态。

- 新增事件：`Start`（Idle→Arming，记录 `startedAtMs` 与 `armed_at_mono_ms`）、`ArmFinished`（Arming→Locked）、`Cancel`（Arming→Idle）。
- `ARMING_MS = 3000` 是常量，不散落魔法数字。
- **到点判定必须加状态前置**：`state == Locked && session.is_some() && elapsed >= target`。Arming 期间 timer 还不存在，任何事件都不得结算。

**判定**：单测 ≥6 条，至少覆盖
1. Idle + Start → Arming（不进 Locked）；
2. Arming + ArmFinished → Locked；
3. Arming + Cancel → Idle，且会话被清空；
4. Arming 期间 Tick（elapsed 很大）**不结算**；
5. Locked 再 Start → `E_STATE_ILLEGAL`；
6. Arming 期间 Finish → `E_STATE_ILLEGAL`。

### S2 起势投影与 Esc 取消（0.5 d）

产出：`views/Arming.vue`、`store` 增加 `arming` 相位、`arming://tick` 事件、`cancel_arming` 命令。

- 倒计时由 **Rust 的 tick 线程**驱动（每 250 ms 推 `arming://tick { remainingMs }`），前端只渲染大号数字，不自己算时间——时间权威只在 Rust（TDD §1.1）。
- 3 秒到点：tick 线程发 `ArmFinished` → 创建计时器 → 入队首写快照 → 推 `state://changed Locked`。
- Esc：前端 `keydown` → `invoke('cancel_arming')` → Rust 校验状态 → 回 Idle（非法状态返回 `E_STATE_ILLEGAL`）。
- 界面文案：`3` / `2` / `1` 大号数字 + 「此时取消还来得及（Esc）」+ 一行小字说明"切走窗口后无法取消，M3 后由结界接管"。

**判定**：点「入关」先看到 3-2-1，3 秒后自动进入闭关页；3 秒内按 Esc 回到配置页且不写 `session.json`；3 秒后按 Esc 无反应。

### S3 钟鸣（0.5 d）

产出：`events.rs` 增加 `Chime { kind, index }`、tick 线程在剩余 10 s / 7 s / 4 s 各推一次 `tick`，`finish()` 推一次 `bell`；前端 `lib/chime.ts` 用 Web Audio 合成。

- 合成方式：正弦基频 880 Hz + 二次谐波，指数衰减包络；`tick` 短（80 ms）、`bell` 长（1.2 s）。**不引入音频文件、不引入依赖。**
- 增益固定 0.6（F-10.3 上限 60%）；系统音量由 OS 混音决定。
- `AudioContext` 在点击「入关」时创建/恢复，避免自动播放策略把首声吞掉。

**判定**：闭关最后 10 秒内能听到 3 声轻滴答；到点能听到 3 声钟鸣。**需要你确认**（我听不到）。

### S4 结算页与「再入一关」（0.5 d）

产出：`views/Settled.vue` 重写、`config.lastDurationMin` 持久化。

- 结算页：本次时长（大号）、结果标签、结果说明一句、`再入一关`、`回到配置`。
- `start_session` 成功后把 `durationMin` 写回 `config.json` 的 `lastDurationMin`；`bootstrap` 已经返回 config，配置页据此预填。
- 「再入一关」= 回配置页 + 预填上次时长，**不自动开始**（F-7.6）。

**判定**：跑完一关点「再入一关」，配置页时长等于上一关；点「入关」还能正常起势（第二关不锁死，M1 的 P0 回归）。

### S5 A-1 全流程连跑 5 次（0.5 d）

- 用临时短时长（1 分钟，验证后立即还原，同 M1 §7.3 的做法）脚本化连跑 5 关：起势 → 闭关 → 到点 → 结算 → 再入一关。
- 每次核对：`records.jsonl` 多一条 `completed`、`session.json` 被删、倒计时在第二关之后仍然推进。
- 25 分钟满时长跑 1 次归人工（标"需要你确认"）。

**判定**：5 次全部结算成功，无卡死、无残留 `session.json`、无重复记录。

### S6 阶段收口（0.5 d）

- 看板与 §7 验收记录、README 同步（起势取消的局限、钟鸣、结算页）。
- `pnpm verify`、`cargo test`、`pnpm test` 全绿，附输出。

## 5. 偏离登记

| # | 偏离 | 原因 | 影响 |
|---|---|---|---|
| D-13 | 静音检测（F-7.3）延后到 M5 | 需要 Core Audio 的 COM 接口，`windows-sys` 不含 COM 接口定义，得引 `windows` crate 的 `Win32_Media_Audio` feature——那是新依赖，需单独拍板 | M2 若系统静音，到点只有画面提示，无文字提示 |
| D-14 | 结算页的累计时长/连续天数（F-7.5）延后到 M5 | `core::stats` 归 M5，M2 造出来是死代码 | 结算页先只显示本次，M5 补两组数字 |
| D-15 | 长老评语（F-7.5 末句、F-7.7 防重复）延后到 M5 | 评语依赖 `quotes.json` 180 条语料，属 M5 内容阶段；先写选择逻辑而无内容是死代码 | 结算页先不显示评语 |
| D-16 | 起势期间 Esc 取消只监听窗口按键 | M2 无全局钩子，Alt+Tab 切走后按 Esc 无效 | README 与起势界面明示，M3 钩子上线后由结界接管 |

## 6. 未验证项与残余风险

- **钟鸣是否真的响**：无法自动化验证，需你确认；若 WebView2 的自动播放策略拦截，第一声可能被吞——已用"点击入关时创建 AudioContext"规避，但仍需实测。
- **多人同时按 Esc 与到点的竞态**：起势结束与 Esc 取消可能同帧到达，靠 `transition` 的状态校验兜底（Arming 已不是当前状态时 `Cancel` 返回 `E_STATE_ILLEGAL`），不会出现半开半关；这条只有单测覆盖。
- **连跑 5 次用的是 1 分钟短时长**，与 25 分钟在"长时内存/句柄泄漏"上不等价，长跑仍归 A-19。
