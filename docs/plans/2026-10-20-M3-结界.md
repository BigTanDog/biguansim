## 1. 目标与不做什么

**目标**：把"显示层覆盖"升级成"真正的结界"——拦键、抢焦点、阻止睡眠、降亮、显示变化自动出关。M3 结束时应达到 A-3 / A-10 / A-12 / A-13 / A-14 全部可验。

**不做（M4 起）**：Esc 长按满 8 秒后的二次确认与抄写（M4 的 `Confirming`）——M3 **只提供 `esc_hold_ms()` 这个事实**，不接流程；冷却/答题/抄写；设置页按钮（M5）。

**M3 必须诚实的三处**：

1. `Ctrl+Alt+Del` 拦不住（PRD §13-1），文档已写明，M3 不尝试。
2. 任务栏"压不压得住"取决于驱动与 DPI，压不住就如实记入 PRD §13-8，不假装拦住了。
3. **`Win+Tab` / 虚拟桌面切换在你的机器上仍有泄漏**（2026-10-20 实测：切到了"桌面 2"）。M3 第一件事是用真钩子复验这一条，见 S2 的验收。

## 3. 步骤序列

### S1 开发期手动退出口（0.3 d）—— 你的测试需要

- 新增 `#[cfg(debug_assertions)]` 命令 `dev_abort`：锁定期间直接收结界、删快照、**不写记录**、日志 `[dev] 手动退出`。
- 前端仅在 `import.meta.env.DEV` 时挂 `Ctrl+Alt+Shift+X`，并在闭关页右下角显示一行灰字 `DEV：Ctrl+Alt+Shift+X 退出`。
- **release 构建里这条命令不存在**（`#[cfg(debug_assertions)]` 编译期剔除），前端也不会渲染——不能成为正式版的逃逸通道。

**判定**：`pnpm tauri dev` 下按组合键立即回配置页且无新记录；`pnpm tauri build` 的产物里 `invoke('dev_abort')` 报命令不存在。

### S2 键盘钩子（1 d）

- `platform::hook`：专用线程装 `WH_KEYBOARD_LL` + `GetMessage` 循环；回调内**只调 `keyfilter::decide`** + 记 Esc 的按下/抬起单调时间戳，其余一概不做（AGENTS §6）。
- `install()` 失败 → `start_session` 回滚并返回 `E_HOOK_FAILED`（PRD D-7：绝不允许"看起来锁了其实没锁"）。
- **60 s 周期重装**：由 hook 线程自己 `Unhook` + `SetWindowsHookEx`，选最近 100 ms 无按键的时刻（`GetLastInputInfo`），失败重试 3 次后推 `notice://toast`。
- 进入 `Locked` 时清空 `ModState`（避免 Arming 期间按住的键串状态）。
- 导出 `esc_hold_ms()`（M4 用来判定 8 秒）。

**判定**：A-3 清单逐条手工过一遍（Alt+Tab / Alt+F4 / Ctrl+Esc / Ctrl+Shift+Esc / Win+E / Win+R / Win+D / Win+Tab / Win+Ctrl+←/→ / 音量键可用 / 打字正常）；日志能看到 60 s 重装；`Esc` 按住 1 s 时 `esc_hold_ms() ≈ 1000`。

**关于 `Win+Tab` 泄漏**：真钩子上线后先单独复验。若仍能切虚拟桌面，说明系统在钩子之外还有路径（很可能来自 `Win` 按下被放行的固有代价），此时**不硬扛**——记录现象，按 PRD §13 补一条局限，并把结论写进 `decisions/005`。备选方案（需你拍板）：进 `Locked` 前调用一次 `IVirtualDesktopManager` 无关操作，或接受泄漏。

### S3 抢焦点（0.5 d）

- `platform::focus`：独立线程 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)` + 消息循环；前台 hwnd 不在我们的窗口集合 → `SetForegroundWindow`。
- 连续 3 次抢回失败 → 降频 500 ms 重试并记 warning，**不放弃**。
- Locked 期间启用，`teardown()` 卸载。

**判定**：用任务管理器/其他程序抢前台，50 ms 内被抢回；人为制造失败（例如在回调里 sleep）时日志出现降频记录。

### S4 阻止睡眠（0.3 d，验证方式已调整）

- 在**独立线程**调 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`，清除时**同线程**调 `ES_CONTINUOUS`（跨线程在部分机型不生效）。
- 不加 `ES_DISPLAY_REQUIRED`：允许熄屏（PRD F-3.8 / D-5）。

**判定（已按台式机现实调整，见 D-23）**：`powercfg /requests` 在闭关期间出现本进程的 `SYSTEM` 请求、出关后消失。原 A-10 的"合盖 10 分钟"口径在本机（台式机、无合盖）无法执行，改为等价验证：闭关期间手动触发休眠（开始菜单 → 睡眠）应当**被阻止**或醒来后剩余时间仍然正确。

### S5 亮度 —— **延后到 v1.0 之后（D-22，2026-10-20 你拍板）**

**原因**：本机是台式机，显示器亮度由显示器自身的物理按键控制，DDC/CI 与 WMI 都改不了；而本阶段唯一的亮度验收（A-14）需要"入关后变暗、出关后还原"的实测，没有可测设备就无法判定，硬做等于交付一段没人验证过的代码。

**保留的接口约定**（不写实现，先写清楚，避免以后改产品口径）：

- `platform::brightness` 将提供 `capture() -> Baseline`、`dim(percent)`、`restore(&Baseline) -> Result<()>` 三个函数，全部返回 `Result`，失败静默跳过（PRD F-3.11）。
- 基线落 `display_baseline.json`，字段与时间戳口径同 §8（`*Ms`）；崩溃后启动时若发现残留基线 → 自动还原并提示。
- DDC/CI 与 WMI 均为**同步阻塞调用**（可达数百毫秒），只能在 io 线程执行（TDD §4.6）。
- 若将来引入 WMI，需要 `windows` crate 的 `Win32_System_Wmi` + `Win32_System_Com` 两个 feature（TDD §2 已预授权"需要 WMI 时局部引入"）。

**连带影响**：A-14 在 v0.1 标"延后，不阻塞发布"；PRD §16 的 M3 验收相应收窄，登记在 §5 D-22。设置页的「恢复默认亮度」按钮（M5）一并延后。

### S6 显示变化检测（0.5 d）

- 每 1 s 取显示器快照（数量 + 各屏分辨率 + DPI，按坐标排序后比对）；**连续 2 次不一致**才判定成立，任一次回到基线即清零。
- 判定成立 → 完整 `teardown()` → `Settled(accident)`、`faults += 1`、toast 说明。
- 不得误判：熄屏唤醒、DPI 未变的窗口重建、显卡驱动瞬时重置。

**判定**：A-12——闭关中拔 HDMI，2 秒内出关并记 `accident`；改缩放同理；熄屏 15 分钟唤醒**不得**触发出关（A-13）。

### S7 联调、熄屏重绘与收口（0.9 d）

- 启动时设 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-features=CalculateNativeWinOcclusion`（TDD §5.4 最后一项），否则熄屏唤醒会先白屏再跳数，U-7 不达标。
- 全量手工验收：A-3 / A-10 / A-12 / A-13 / A-14；A-9 的界面红字（M2 未实测）。
- 看板、README、`decisions/005`（拦键泄漏结论）。

## 6. 未验证项与残余风险

- **钩子被安全软件拦截**：安装失败必须拒绝入关，否则"以为锁了其实没锁"；这条要在你的机器上实测一次。
- **WMI 与 DDC/CI 在特定显示器上失败**：静默跳过是设计，但不能变成"永远跳过还没人知道"——日志要能一眼看出"跳过了哪块屏"。
- **`Win+Tab` 泄漏**：见 S2；若确认存在且不可消除，它会让"结界"在 PRD 里多一条已知局限，需你拍板改 PRD §13。
- **抢焦点在系统安全桌面切换时**：收不到事件，属预期，不处理。
