## 1. 目标与不做什么

**目标**：让「出去」这条路从"没有"变成"很贵"——`Locked → Cool → Challenge →（Copying）→ Settled(early)`，外加 `Confirming → Settled(emergency)`。M4 结束后应达到 A-4 ~ A-8、A-21、A-22、A-23、A-25 全部可验。

**不做**：
- 60 题题库、180 条语料、10 段抄写的**全量内容**与记忆衰减/退化（A-15、A-24 属 M5）。M4 只入最小可用真实内容，见 S3 与 D-25。
- 记录页 / 题库页 / 设置页 / 首次引导（M5）。
- 亮度（已延后，D-22）。

**M4 必须诚实的三处**：

1. **`Win` 键至今没拦住**（你 2026-10-20 真机复验：单击仍唤出、`Win+D` 能逃到桌面）。这是第三次尝试失败，按 AGENTS §2 停止加码，转为**收窄 A-3 + 写进 PRD §13**，需你拍板（§8-1）。M4 只保证"漏出去也能 1 秒内收回"，不再保证"拦得住"。
2. **抄写可能被输入法拖累**。抄写要打中文，而抢焦点会在候选窗出现时反复把前台抢回来，可能打断输入。M4 用"抄写/确认期间暂停抢焦点"规避，但真机手感只能你试（`unverified`，见 §7）。
3. **题库内容量不足会显示"阵法简陋"**。M4 的题库只有 12 题（< 30），配置页与闭关页会按 F-8.3 显示黄字——**这是真话，不许藏**。

## 3. 设计定案（本阶段钉死，执行中不再改）

### 3.1 八态与转移表（PRD §5.2 原样落地）

`Idle / Arming / Locked / Cool / Challenge / Copying / Confirming / Settled`
（`Recovered` 不是状态，是启动弹窗，仍在 `runtime.recovered`。）

| 当前 | 事件 | 下一 | 副作用 |
|---|---|---|---|
| Locked | `RequestUnlock`，且 `remaining ≥ cooldown(n)` | Cool | `n = attempts+1`；`attempts = n`；`cool_end = elapsed + cooldown(n)` |
| Locked | `RequestUnlock`，且 `remaining < cooldown(n)` | **不转移** | 返回 `Refused { needMs, remainingMs }`（F-4.5 / A-22） |
| Cool | `CoolFinished { round }` | Challenge | 存 round（题目已打乱、不含答案） |
| Challenge | `SubmitChoice` **全对** 且 `copy_chars(n) = 0` | Settled(early) | — |
| Challenge | `SubmitChoice` **全对** 且 `copy_chars(n) > 0` | Copying | 存抄写任务 |
| Challenge | `SubmitChoice` **任一错** | Cool | `attempts += 1`；`cool_end = elapsed + cooldown(attempts)`；不公布答案 |
| Copying | `SubmitCopy` 逐字一致 | Settled(early) | — |
| Locked | `RequestEmergency`（调用方已校验 `esc_hold_ms() ≥ 8000`） | Confirming | `esc_consume()` |
| Confirming | `ConfirmEmergency`（调用方已校验 9 字） | Settled(emergency) | `faults += 1` |
| Confirming | `CancelEmergency` | Locked | `esc_consume()` |
| 任意活跃态 | `Finish { Accident }`（显示变化） | Settled(accident) | `faults += 1` |
| **任意活跃态** | **`Tick` 且 `elapsed ≥ target`** | **Settled(completed)** | **全局规则，仍只在 `transition()` 开头实现一处** |

两点口径补充：
- **活跃态** = `Locked | Cool | Challenge | Copying | Confirming`。到点规则对五态一视同仁；`Arming` 仍不参与（计时器未启动）。
- `Finish { Accident }` 允许从 Cool/Challenge/Copying/Confirming 发起（PRD §5.2 只写了 Locked，但不允许的话"冷却中拔屏"会卡在坏布局里，违反 D-6「宁可让用户逃一次」）。这是**放宽**，登记在 D-26。

### 3.2 成本公式（`core/cost.rs`，纯函数，全部单测）

```
cooldown_ms(n, base)  = min(base + 5 × (n-1), 20) 分钟      base 取自 config.cooldownBase（3–10）
question_count(n, qb) = clamp(min(qb + (n-1), 5), 3, 5)     qb 取自 config.questionBase（3–5）
copy_chars(n)         = n >= 4 ? 200 : (n == 3 ? 100 : 0)
```
`n` 为本次闭关第 n 次尝试，**单调递增不清零**（D-3）。`n = 0` 防御性按 1 处理。

### 3.3 冷却用单调计时，不用墙钟

`cool_end_elapsed_ms` 存在 `SessionInfo` 里，与 `elapsed_ms` 同一坐标系（单调 + 睡眠累计）。理由：用户改系统时间不该能缩短冷却，而墙钟可以。`session.json` 的 `cooldownUntilMs` 字段保留，只由 `wall_now + (cool_end - elapsed)` 换算后写入快照，**不参与任何判定**。

### 3.4 数据归属（避免双锁与状态分叉）

| 数据 | 归属 | 理由 |
|---|---|---|
| 题库（12 题） | `Runtime.bank: Mutex<Arc<Bank>>`，`init` 与 `start_session` 时加载 | 只有抽题时读，不进 `SessionInfo`（后者每 250 ms 被 clone） |
| 当前轮题目（已打乱） | `SessionInfo.round: Option<challenge::Round>` | 与状态同锁，杜绝"状态是 Challenge 但题目没了" |
| 抄写任务（原文 + 目标字数） | `SessionInfo.copy: Option<challenge::CopyTask>` | 同上 |
| 成本参数 | `SessionInfo.cooldown_base / question_base`（`Start` 时从 config 带入） | 状态机自足，不读文件 |

**锁顺序仍只有一把**：`timer → machine`（`SessionInfo` 里的一切都在 machine 锁内）。不新增第三把锁。

### 3.5 判定留在 Rust 的三处铁律

1. `submit_choice` 只接受**展示索引 0–3**，映射与答案都在 `challenge::Round` 里，越界返回 `E_INVALID_CHOICE`。
2. 任何响应体、任何事件载荷**不含 `answer`**（用序列化断言测，A-25a）。
3. `request_emergency` 与 `confirm_emergency` 的合格判定都在 Rust（前者看 `esc_hold_ms()`，后者逐字比对 9 字）。

### 3.6 事件与命令契约

**新增事件**（TDD §5.2 同步）：

| 事件 | 载荷 | 频率 |
|---|---|---|
| `cool://tick` | `{ remainMs }` | 1 s，仅 Cool |
| `esc://hold` | `{ heldMs }` | 100 ms，仅 Locked 且按住时（松开补发一次 0） |

**`state://changed` 扩一个字段**：

```ts
interface StateChanged {
  state: 'Idle'|'Arming'|'Locked'|'Cool'|'Challenge'|'Copying'|'Confirming'|'Settled'
  result: string | null
  goal: string | null
  elapsedMs: number
  targetMs: number
  payload: PhasePayload | null   // 按 state 二选一，serde tag = "kind"
}
// Cool     → { kind:'cool', attempt, cooldownMs }
// Challenge→ { kind:'challenge', index, total, stem, options[], attempt }
// Copying  → { kind:'copy', text, chars }
// Confirming→{ kind:'confirm', sentence, elapsedMs, faults }
```

**命令**：

| 命令 | 入参 | 返回 | 备注 |
|---|---|---|---|
| `request_unlock` | — | `{ attempt, cooldownMs }` | 不足一次冷却 → `E_REMAIN_TOO_SHORT`（**新增错误码**，UI 显示 F-4.5 固定句） |
| `submit_choice` | `{ questionId, choice }` | `{ correct, next?: {index,total,stem,options[]}, copy?: {kind:'copy',...}, cool?: {attempt,cooldownMs} }` | 错 → 直接回 Cool，`next` 为空 |
| `submit_copy` | `{ text }` | `{ ok, mismatchIndex }` | 不归一化全角半角 |
| `confirm_emergency` | `{ text }` | `{ ok }` | 不一致 → `E_CONFIRM_MISMATCH`（**新增**） |
| `cancel_emergency` | — | `{}` | 回 Locked，不消耗成本 |
| `get_state` | — | 全量状态 + 上述 `payload` | **吸收原 `get_current_question`**（D-27） |

**契约变更（需报告）**：`request_emergency` **不作为命令实现**——8 秒判定由 tick 线程在 Locked 下自动触发，前端只画进度环。理由：前端若卡住/被覆盖，用户就再也破不了戒；自动触发少一条链路。`get_current_question` 并入 `get_state`，避免两条重绘路径给出不一致的题。

### 3.7 前端：仍是 `Lock.vue` 一个页面五种投影

不按状态拆窗口（TDD §6.3）。组件拆分控制在 400 行内：

```
views/Lock.vue              环 + 倒计时 + 页眉 + 投影分发（< 250 行）
components/ExitPanel.vue    Cool 固定语与分钟粒度、Challenge 题干与四选项
components/CopyPanel.vue    原文对照 + textarea + 逐字标红 + 「已抄完」
components/ConfirmPanel.vue 9 字输入 + 代价公示三行 + 「再坐一会」
components/EscRing.vue      破戒进度环（读 esc://hold）
```

抄写的"错字标红"由前端拿原文做**展示层**比对（原文不是秘密）；**通过与否**只认 `submit_copy` 的返回（TDD §5.1）。

### 3.8 抄写/确认期间暂停抢焦点

`focus::pause()` / `focus::resume()`（原子开关，回调里只读一个 bool）。理由：中文输入法的候选窗是别的线程/进程，抢焦点会反复把前台夺回来，可能打断输入法。用户此时只在本窗口输入，暂停没有安全代价。

### S0 真机回归修复（0.5 d）——你这次自测暴露的三个问题

| 问题 | 根因（已定位，不靠猜） | 修法 |
|---|---|---|
| **`Win+D` 能逃到桌面，且之后键盘半死、必须杀进程** | `overlay::spawn_topmost_keeper` 只重申 topmost，**从不取消最小化**；`focus::try_reclaim` 在"前台仍是本进程窗口但已最小化"时因 `pid == our_pid()` 直接 `return true`，于是既不还原也不报错 | ①`focus::try_reclaim` 先 `IsIconic(target)` → `ShowWindow(SW_RESTORE)` 再比 pid；②keeper 每秒检查 `is_minimized()` → `unminimize()` + 重新置顶；③日志记一次 `[focus] 窗口被最小化，已还原` |
| **`Ctrl+Alt+Shift+X` 退出无效** | 组合键里 X 本应放行（`decide` 的 Alt 分支只吞 Tab/Esc/F4/Space），所以更可能是 WebView 侧没收到或 `dev_abort` 没生效——**未定论** | ①`keyfilter` 加一条 `#[cfg(debug_assertions)]` 显式放行 Ctrl+Alt+Shift+X 并有单测（把可能性掐掉）；②前端 keydown 打 `console` + `invoke('dev_abort')` 失败时弹 toast（看得见才有得报）；③闭关页 DEV 退出按钮改成右下角显眼一条（鼠标路径永远可用，你的建议） |
| **`Win` 单击仍唤出开始菜单** | 三次策略均未在真机拦住（004 §4 已预判此分支） | **不再加码**。S0 只做：A-3 收窄 + `decisions/006` 落结论 + PRD §13 待你拍板 |

### S1 钩子的 Esc 消费语义（0.2 d）

- `hook::esc_consume()`：把 `ESC_DOWN_MS` 清零并要求重新按下才重新计时。给"取消破戒后 Esc 仍被按住"这个场景用——否则切回 Locked 会立刻二次触发（F-6.4 的"进度清零"）。
- 不加锁、不加分配，只一个 `AtomicU64::store`。

**判定**：单测覆盖 `decide` 的 Esc 分支；`esc_consume` 的行为靠 S7 手工（长按 8 秒 → 取消 → 不弹第二次）。

## 7. 未验证项与残余风险

1. **中文输入法 + 抢焦点**（风险最高）：抄写要输入中文，候选窗可能被抢焦点打断。已用 `focus::pause()` 规避，但**必须你实测**；若仍不可用，退路是抄写改为"逐字点击下方字块"（成本与情绪都更差，需你拍板）。
2. **`Win` 键仍未拦住**：即使 S0 让 `Win+D` 1 秒内收回，画面仍会闪一下桌面；开始菜单也仍可能弹出。PRD §13 需要新条目（§8-1）。
3. **冷却期间拔屏/改缩放**：走 D-26 的放宽路径，逻辑上有单测，真机只有单屏，标"未验证"。
4. **`esc://hold` 100 ms 事件的 CPU**：只在按住时发，预计可忽略；若你观察到占用上升，改 250 ms（进度环仍够顺滑）。
5. **题库 12 题会被你 3 轮背熟**：M4 期间只够验证机制，不构成真实防线（M5 补齐）。
