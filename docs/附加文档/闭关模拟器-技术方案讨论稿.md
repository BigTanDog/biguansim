## 2. 第一处必须改：不要"前后端分离"

你说"前后端分开比较好，后端只存题目"。这在 Web 里成立，在本地桌面应用里会变成**安全漏洞**：

> 一旦后端跑在 `127.0.0.1:8000`，那"解锁"这个动作就变成了一个 HTTP 接口。  
> 用户只需要在浏览器地址栏敲 `http://127.0.0.1:8000/api/session/unlock`，或者按 F12 在控制台 `fetch(...)`，  
> 或者更有趣——**你闭关时随便打开一个网页，那个网页里的 JS 就能 POST 到你的本地端口**（CSRF），把锁解了。

也就是说：**你花两周做的所有防绕过，会被一个 URL 打穿。** 而且本地端口还带来端口冲突、防火墙提示、多实例竞争一堆杂事。

**正确做法：分层，不分离。**

```
┌─────────────────────────────────────────┐
│  UI 层（Web 前端，跑在 WebView2 里）      │  ← 只负责画和收集输入
│  Vue/React + TS                          │
└──────────────┬──────────────────────────┘
               │  IPC（Tauri command，进程内调用，无端口、无网络）
┌──────────────▼──────────────────────────┐
│  领域层（Rust / C#）                      │  ← 会话状态机、计时、判题、记录
│  session / timer / question / record     │
└──────────────┬──────────────────────────┘
               │  直接调用
┌──────────────▼──────────────────────────┐
│  系统层（Win32）                          │  ← 钩子、置顶多屏、抢焦点、单调时钟
└──────────────┬──────────────────────────┘
               │  文件 IO
┌──────────────▼──────────────────────────┐
│  存储层：%APPDATA%\闭关模拟器\*.json      │
└─────────────────────────────────────────┘
```

**"后端"该有的东西一个不少**（状态机、判题、持久化都在领域层），只是**不出进程、不开端口**。UI 换技术栈也不影响领域层——这就是你要的"分开"的真实价值，用分层就拿全了。

> 唯一需要真·双进程的场景是 L2 的守护进程（UI 被杀后重启它）。你选了 L1，所以现在完全不需要。

### 3.2 我的建议

**首选 Tauri 2**，理由是三条硬的：

1. 你要的界面（底部 RPG 对话框、环形进度、极缓呼吸动效、浅阵法叠加）在 CSS 里是几小时的事，WPF 里是几天的事；
2. 10 MB 的绿色文件夹，复制给道友就能跑，符合"少数人自用"；
3. `resources/` 可以内嵌阵法图与音效，用户数据另放 AppData，升级不覆盖题库。

**但有个前提**：Rust 那一层必须**只写系统调用，不写业务**。也就是：

```
src-tauri/src/win/
├─ hook.rs      SetWindowsHookEx(WH_KEYBOARD_LL) + 放行/拦截表    ~120 行
├─ overlay.rs   EnumDisplayMonitors + 每屏一个 topmost 无边框窗口  ~90 行
├─ focus.rs     SetWinEventHook(EVENT_SYSTEM_FOREGROUND) 抢回焦点  ~50 行
├─ clock.rs     QueryUnbiasedInterruptTime + 墙钟交叉校验          ~40 行
└─ power.rs     SetThreadExecutionState 阻止睡眠（见 9.1）         ~20 行
```

业务全在 TS 侧（状态机、判题、文案、UI）。**这样即使 Rust 部分出问题，也只影响"锁不锁得住"，不会影响"数据会不会坏"。**

> 如果你**完全不想碰 Rust**：直接上 WPF。你会损失一些动效，但能在两周内用上，而"用上"比"做得漂亮"重要。

### 3.3 关键系统调用的真相（提前避坑）

| 目标                                  | API                                                                | 坑                                              |
| ----------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| 拦 Alt+Tab / Win / Ctrl+Esc / Alt+F4 | `WH_KEYBOARD_LL` 全局钩子                                              | 回调超过约 1 s 会被系统静默摘下，且**必须**在带消息循环的线程安装          |
| 拦 Ctrl+Shift+Esc（任务管理器）             | 同上，**不需要改注册表**                                                     | 这是零误报的高性价比做法，比 `DisableTaskMgr` 干净得多           |
| 覆盖多屏                                | 每屏一个 topmost 无边框窗口                                                 | DPI 必须 Per-Monitor V2，否则 4K+1080p 混合屏会错位       |
| 防止焦点跑到别处                            | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` + `SetForegroundWindow` | 这个 API **不激进、几乎不误报**，比"锁键盘"更值得做                |
| 防改系统时间                              | `QueryUnbiasedInterruptTime`（单调）+ 墙钟 `GetSystemTimeAsFileTime`     | 单调值**不含睡眠时间**，必须与墙钟交叉取 max，否则睡 2 小时白赚          |
| `Ctrl+Alt+Del`                      | —                                                                  | **拦不住**，这是内核安全序列。接受它，并当成"保命通道"写进说明             |
| 触控板三指上滑（任务视图）                       | —                                                                  | **L1 拦不住**（不是键盘消息）。只能在设置页提示用户关掉手势。这是真实漏洞，别装作没有 |

## 4. 打包与分发（回答你第 12 问）

**你的直觉是对的：不要做成单文件 exe。** 原因：

- 单文件发布要解压到 `%TEMP%`，**启发式引擎最爱盯这个行为**；
- 启动慢 1–3 秒（每次解压），而闭关软件会被频繁启动；
- 出问题时无法单独替换资源。

**正确结构（就是你说的"文件夹 + exe"）：**

```
闭关模拟器-v0.1.0-win64\
├─ 闭关模拟器.exe            ← 启动器 + 主程序
├─ 资源内嵌（阵法图/音效/种子题库打包进 exe 内部，不散落）
└─ 卸载说明.txt
```

用户数据另放（升级不覆盖、可手动备份）：

```
%APPDATA%\闭关模拟器\
├─ config.json        设置
├─ bank\              题库（seed.json 首次从内嵌复制，可自行增删）
├─ records.jsonl      闭关流水（一行一次，永不改写，方便回看）
└─ session.json       崩溃恢复快照（每次闭关中每 15 s 覆写）
```

**版本更新**：关于页显示 `v0.1.0 (git abc1234)` + 一个按钮"打开 GitHub 仓库"。  
你手动 `git pull` + 重新 build。**不做自动更新**——自动更新需要签名证书 + 服务器 + 权限，收益为零，风险全是你的。

**分发**：直接压 zip 发给道友。首启会被 SmartScreen 拦（"未知发布者"），说明里写清楚"点 更多信息 → 仍要运行"。  
如果以后真要做大：OV 代码签名约 2000–4000 元/年，那时再说。

## 6. 会话状态机 + 退出成本（核心）

状态机（也是我要给你看的第一张图）：

```
Idle ──开始──▶ Arming(3-2-1，防误触) ──▶ Locked
                                          │
        ┌─────────────────────────────────┼──────────────────┐
        │ 点"解开"                         │ 到点              │ 长按 Esc 8s
        ▼                                 ▼                  ▼
     Cool(冷却 N 分钟) ──▶ Challenge(答题)   Settled(完成)    Settled(紧急破戒)
                              │ 答错
                              └──▶ 训话 → 回 Cool（成本+1）
                              │ 全对
                              ▼
                          Settled(提前出关)

任意状态崩溃/被杀 ──▶ 下次启动：Recovered（自动解锁 + 记一笔，绝不续锁）
```

### 6.1 你第 10 条有个漏洞：**答错不该让成本归零**

你的设计是"答错 → 训话 → 重抽 → 重新计时"。问题在于：**重抽等于洗牌，尝试次数无限，成本不递增。**  
题库再大，用户也有"会做的题"；只要试到第 5 次、第 8 次，总会撞上。摩擦是固定的，而冲动是波动的——总有一次会过。

**改成成本递增（单调、不归零）：**

| 第 n 次尝试 | 冷却         | 题数 | 附加                       |
| ------- | ---------- | -- | ------------------------ |
| 1       | 5 min      | 3  | —                        |
| 2       | 10 min     | 4  | —                        |
| 3       | 15 min     | 5  | 追加抄写 100 字               |
| 4+      | 20 min（封顶） | 5  | 抄写 200 字 + 显示"今日已尝试 4 次" |

这个曲线只改一个变量（`attempts`），实现 20 行代码，但**防御强度提升一个量级**——因为第 3 次时你已经多花了 30 分钟，冲动早就凉了。

### 6.2 更狠的一招：题库记忆衰减（防背题）

你的题库如果只有 30 题，一周就背完了。做一个反向间隔重复：

- 每题记录"最近出现时间 / 答对次数"；
- **答对过的题，30 天内不再抽**；
- 题库 < 30 题时，退出页顶部显示黄字："**阵法简陋（题库仅 12 题），易被强破**"。

这句提示本身就是最好的产品设计——把"你需要多做题库"变成用户自己的诉求。

### 6.3 紧急通道的真实成本（你第 3 条）

你说"允许，但记一过"。**如果只是记一过，它就会变成主按钮。** 人类对"记一笔"的恐惧远小于"等 20 分钟"。

让它**体面但昂贵**：

1. 长按 Esc 8 秒（有进度环，手会酸）；
2. 弹窗要求输入整句：`我确认放弃本次闭关`（打错重来）；
3. 显示实时代价：`本次 1 小时 12 分将不计入累计 · 连续闭关 6 天将归零 · 道行 -30`；
4. 确认后解锁，记录 `破戒(紧急)`。

**不做三次"你确定吗"**——那是折磨，不是成本。一次到位、代价真实，才叫设计。

## 7. 数据模型（草案）

```jsonc
// bank/seed.json
{
  "version": 1,
  "name": "基础阵法",
  "questions": [
    { "id": "q001", "type": "choice", "difficulty": "undergrad",
      "stem": "∫₀¹ x² dx = ?",
      "options": ["1/2", "1/3", "1/4", "1"],
      "answer": 1,                        // 存索引，不存字母（选项会打乱）
      "tags": ["math"], "source": "generated" },
    { "id": "q002", "type": "fill", "difficulty": "undergrad",
      "stem": "sin x 的导数是？",
      "accept": ["cos x", "cosx", "cos(x)"],   // 多答案 + 归一化匹配
      "tags": ["math"] }
  ]
}

// records.jsonl  ← 一行一次，只追加
{"id":"s_20261019_1","startedAt":"2026-10-19T20:00:00+08:00","plannedMs":7200000,
 "actualMs":7200000,"result":"completed","attempts":0,"questionsAsked":0}

// session.json  ← 运行中每 15 s 覆写
{"state":"Locked","targetMs":7200000,"elapsedMs":1830000,
 "monoBase":123456,"wallBase":"...","attempts":1,"cooldownUntil":null}
```

**判分要点**：

- 选择题**每次打乱选项顺序**（防"选第三个"记忆），答案存原始索引；
- 填空题归一化：全角→半角、去空格、大小写、中英文标点，再与 `accept` 数组任一匹配；
- 3 题全对概率（4 选 1）= 1.56%，**蒙不过去**，这点你的设计是成立的；
- 所以**不需要**把题出得多难，**需要的是"必须全对"**。

## 8. UI 结构（回应你第 11 条）

你的方向是对的，补四条具体建议：

**① RPG 对话框放在底部是对的**，但不是因为它"像游戏"，而是因为**视觉重心低 = 不挡抬头思考**，且 JRPG 玩家天生知道"点这里继续"。对话框里应该只有三种内容：**叙述（长老说话）/ 选项列表 / 单行输入**，不要塞按钮组。

**② 环形进度**：外环用 1px 描边式细环（粗环在 4 小时里会看腻），中间是剩余时间（等宽数字防跳动），下方小字"已坚持 · 目标"。  
**别做百分比**——"还剩 1 小时 47 分"比"剩 74%"更有压迫感，也更像修行。

**③ 系统时间"较小不起眼"——我建议改成"校验时钟"**：右下角 11px 灰字 `系统 21:03 · 一致`。  
它不只是装饰，是**防改时间的证据**：用户改过系统时间回来，这里会显示 `不一致`，那一瞬间的羞耻感比任何弹窗都有效。

**④ 纯色背景 + 浅阵法：请务必加两条保命规则**

- **每 10 分钟把阵法图案平移 2px**（肉眼几乎无感）→ 防 OLED 烧屏，4 小时静止图案是真的会留影；
- **允许显示器自动熄屏**（见 9.1），这既省电、防烧屏，也**降低分心**——屏幕亮着就是诱惑。

## 9. 第二轮拷打：13 个会让人放弃使用的问题

### 9.1 【最致命】静修模式下，你会离开电脑 → 系统自动熄屏/睡眠

这是整个方案里**最容易被忽略、但 100% 会发生**的事：

- 你不在电脑前 = 无键鼠输入 = 10 分钟后熄屏，30 分钟后睡眠；
- 进入睡眠后，全屏窗口"消失"了（在锁屏后），你回来唤醒需要登录，登录后窗口还在 —— 这一环**没问题**；
- 但如果你设的是"从不睡眠"之外的电源计划，**钩子所在的线程可能随睡眠一起挂起**，醒来后钩子失效 → 锁形同虚设。

**方案**：闭关开始时调

- `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` → **阻止睡眠**（保住钩子与计时）；
- **不加** `ES_DISPLAY_REQUIRED` → **允许熄屏**（省电、防烧屏、少诱惑）。

结束/紧急退出时 `SetThreadExecutionState(ES_CONTINUOUS)` 还原。  
并在首启说明里写一句："闭关中屏幕会黑，按任意键唤醒即可看到倒计时，计时不受影响。"

### 9.2 触控板手势能破 L1

三指上滑 = 任务视图，四指左右 = 切虚拟桌面。**不是键盘消息，钩子拦不到。**  
→ 设置页给一条"加固建议：关闭三指/四指手势"，并在压力测试清单里当作已知项。

### 9.3 `Ctrl+Shift+Esc` 你没打算拦，但成本极低

它不走注册表，钩子就能拦，且几乎没有误报。**建议拦掉**——拦住它，普通用户就没有任务管理器入口了（`Ctrl+Alt+Del` 那条路拦不住，但门槛已经够高）。

### 9.4 到点提示音的三个坑

- 用户静音 → 无提示；→ 开始时检测静音，提示"静音状态下到点只有画面提示"；
- 用户戴耳机但音量 3% → 听不见；→ 循环提示 3 次，每次间隔 5 s；
- 音量 100% 突然炸响 → 被骂。→ 用系统音量的 60%，上限 60%。

### 9.5 4 小时闭关的"存在性焦虑"

只显示倒计时，第 40 分钟你会开始烦躁，第 90 分钟会开始怀疑人生。  
→ 开始前让用户填**一行本次目标**（"背完 List 5–7"），闭关页常驻显示。这一行字的留人效果远超任何动效。

### 9.6 文案会枯竭

"长老训话"是这个产品的灵魂，但写 30 条就会重复。  
→ 分三阶段（0–30 min 试探期 / 30–90 min 心魔期 / 90 min+ 破境期），每阶段 40 条，用变量拼（本次时长/累计天数/历史成功次数），400 种组合足够用一年。

### 9.7 填空题是体验杀手

中文输入法、全角半角、`sin x` 还是 `sinx` —— 用户会被自己气死。  
→ **MVP 只做选择题**，填空放 V2 且仅用于英文/数字答案。

### 9.8 题库版权

考研真题、教材课后题都有版权。**"开发者大礼包"不能直接放真题。**  
→ 自己写/AI 生成 + 只做"导入格式"不提供内容。

### 9.9 多屏用户的第一分钟


接了两块屏，如果只覆盖主屏，剩下那块就是天堂。
→ `EnumDisplayMonitors` 每屏一个窗口，**MVP 就必须做**（不是 V2）。

### 9.10 分辨率/缩放变化
用户闭关中途拔掉外接屏、或改缩放 → 窗口跑到屏幕外，按钮点不到 = 锁死。
→ 监听 `WM_DISPLAYCHANGE`，重算布局；并在 Arming 阶段就检查"当前是否多屏"给出提示。

### 9.11 杀软误报的"三条红线"
只要不碰这三样，Tauri/WPF 的 exe 基本不会被报：
① 不写入 `Run`/计划任务（你不做自启 ✅）② 不改注册表策略（L1 不做 ✅）③ 不注入/不挂钩其他进程（只做全局键盘钩子，属灰区但常见）。
→ 你已经天然满足，**别在 V2 加"硬核模式"时破坏它**（可以做成"独立 exe 插件"，主程序永不联网不写注册表）。

### 9.12 "炫耀"这个需求值得做，而且零成本
你说"不上传，只是炫耀"。→ 结算页一个按钮：**导出闭关战报 PNG**（本地 Canvas 渲染：本次时长、累计、连续天数、境界、一句语录）。发群里就是社交货币，比任何排行榜都省钱。

### 9.13 番茄钟会跟"静修模式"打架
25 分钟学习 + 5 分钟休息，休息时要不要解锁电脑？要，那 5 分钟就是刷手机入口；不要，那"休息"没意义。
→ **MVP 不做番茄循环**。短时长（25/45 min）就当一个完整的闭关，结束即自由。

## 10. MVP 里程碑（约 3 周，可压缩到 2 周）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M1（3天） | 骨架：Tauri 工程 + 全屏置顶 + 多屏 + 单调计时 + 崩溃快照 | 手动 kill 进程后重启不续锁，计时与真实时间误差 < 1 s/小时 |
| M2（3天） | Arming → Locked → 到点 Settled 全流程 + 提示音 | 连跑 5 次 25 分钟闭关，无一次卡死 |
| M3（4天） | 拦截层：键盘钩子 + 焦点抢回 + 电源状态 + 手势提示 | Alt+Tab/Win/Ctrl+Esc/Ctrl+Shift+Esc 全部失效；音量键可用 |
| M4（4天） | 退出流程：冷却 + 抽题 + 判分 + 成本递增 + 紧急通道 | 连续尝试 5 次，冷却与题数按表递增且不归零 |
| M5（3天） | 记录页 + 结算页 + 战报导出 + 60 题种子题库 | 记录可查、可导出、答对过的题 30 天内不再出现 |

**第 2 周末必须自己真用 3 天**（每天 2 小时以上）。这一步的反馈价值 > 再写一周代码。
