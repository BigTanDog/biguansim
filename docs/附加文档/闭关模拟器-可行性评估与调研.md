> 评估对象：《闭关模拟器-说明.md》  
> 评估日期：2026-10-19  
> 结论口径：技术可行性 / 设计合理性 / 竞品现状 / 待定问题 四块

## 一、结论先行（TL;DR）

| 维度            | 结论                                                                          |
| ------------- | --------------------------------------------------------------------------- |
| **技术可行性**     | **高**。核心机制（全屏置顶 + 计时 + 键盘钩子 + 题库解锁）全是成熟 Win32 能力，单人 2–4 周可做出可用版本。           |
| **"锁死"可行性**   | **不可能锁死**。用户态程序无法拦截 `Ctrl+Alt+Del`（安全桌面）、安全模式、拔电源、第二个管理员账户。这是操作系统设计，不是技术难点。 |
| **产品定位风险**    | **中高**。存在一个必须先回答的根本矛盾：**"接管桌面"和"在电脑上学习"互斥**。                                |
| **"答题解锁"有效性** | **偏弱**。知识题可查、自设题可记、乱写题等于随机密码——它只是"摩擦"，不是"门锁"。真正有效的杠杆是**冷却期**，不是题目难度。        |
| **竞品空白**      | **桌面端"题库答题解锁"确实几乎没人做**（现有产品用打字、数学题、第三方验证）。空白既是机会，也说明单靠它撑不起需求。               |
| **最大落地风险**    | **杀软误报**。低层键盘钩子 + 禁用任务管理器 + 自启动 + 全屏置顶，特征组合与"锁屏勒索软件"高度重合。                   |

**一句话判断**：这个想法技术上完全做得出来，但它的成败不在"锁得多死"，而在"**退出摩擦是否大于冲动持续时间**"和"**闭关期间是否真的有事可做**"。把精力放在这两件事上，比研究怎么禁任务管理器回报高得多。

## 二、设计合理性评估

### 2.1 三条硬伤（按严重度排序）

#### 硬伤 1：定位自相矛盾 —— 锁了电脑，用什么学习？

说明书写的是"全屏接管桌面，形成保护壁纸"。那么闭关期间：

- 如果**不能**用电脑 → 这是"戒断工具"，适用于背单词、刷纸面题、看书。但"学习"场景里有一大类（网课、PDF、Anki、写代码、写论文）直接失效。
- 如果**能用**部分软件 → 就必须做应用白名单/桌面隔离，锁定强度大幅下降，且白名单本身是新的绕过面（浏览器白名单 → 上网页；PDF 阅读器白名单 → 打开别的 PDF 无所谓，但资源管理器呢）。

**建议**：不要试图一个模式通吃。做成两个明确的档位：

- **静修模式（离开屏幕）**：全屏壁纸 + 倒计时 + 白噪音。电脑只是"被占用的桌面"。锁得可以很硬。
- **研习模式（在机学习）**：只允许白名单程序（阅读器/笔记/IDE），其余全部遮挡。锁得软，但可用。

这个划分会直接决定 UI、权限、防绕过等级，属于**开工前必须定死**的第一件事。

#### 硬伤 2："题目越复杂越好"方向错了

你在说明书第 4 条里写"题目是越复杂越好，哪怕都是乱写的"。这句话其实自己已经说出了真相：**既然是乱写的，那它就不是题，是密码。**

而"密码"防不住三种情况：

1. **写下来了**：纸上、手机备忘录、微信文件传输助手。
2. **背下来了**：真按你说的"乱写"，人反而更容易记住自己造的怪词。
3. **知识题可查**：大学知识的题，手机一拍一搜就出来，或者干脆切到另一个设备。

更关键的是：**题目难度和"防止冲动退出"之间没有因果关系**。冲动持续 30 秒到 3 分钟；一道 5 分钟的题确实能挡住；但如果用户真的有急事（拉肚子、外卖、老板电话），它变成纯粹的伤害。

**建议**：把"退出成本"重构为一个**阶梯**，把最有效的放第一层：

| 层级 | 机制                                                                       | 挡冲动效果 | 副作用     | 建议                      |
| -- | ------------------------------------------------------------------------ | ----- | ------- | ----------------------- |
| ①  | **冷却期**：点击退出后强制等待 3–10 分钟（可配置，且**不可跳过**，倒计时期间界面只显示"你真的要放弃吗 + 已坚持 xx 分钟"） | ★★★★★ | 极小      | **必做，这是核心**             |
| ②  | **承诺可视化**：显示"本次已投入 47 分钟，退出将作废并记入`破戒`记录（累计 3 次）"                         | ★★★★  | 极小      | 必做                      |
| ③  | **长文本抄写**：复制一段随机中文/文言 200–300 字，逐字校验                                     | ★★★★  | 小       | 必做（替代"乱写题"）             |
| ④  | **第三方验证**：退出码发到朋友微信/邮箱，或需要对方输入                                           | ★★★★★ | 需网络/社交  | V2 可选（ZenLock 的做法，实测有效） |
| ⑤  | **知识题**：题库随机抽 3–5 题，全对才放行                                                | ★★    | 可查、可能过难 | 保留，作为"仪式感"而非防线          |

**结论：把"冷却期"当主防线，"答题"当仪式感。** 这样即使题目被搜到，你也已经多等了 5 分钟，冲动基本过去了。

#### 硬伤 3：没有保命通道 = 产品会变成砖

全屏 + 锁键鼠 + 到点才解。那么以下任何一种情况都会让用户当场骂娘：

- 程序崩溃 / 死循环 / 钩子把系统输入吃掉
- 用户突发身体不适
- 老板/家人要用这台电脑
- 断电重启后程序自启动又立刻锁上（最恶劣）
- 显示器分辨率/缩放变化导致窗口跑出屏幕，按钮点不到

**建议（硬性要求）**：

1. **致命逃生通道**：`长按 Esc 8 秒` 或 `连按 F12 五次` → 直接解锁，但记一条 `破戒（紧急）`。宁可被滥用也不能让人锁死。
2. **崩溃自恢复**：主进程崩溃/被杀 → 记录会话快照；下次启动若发现"上次会话未正常结束"，**自动解除锁定**，只在日志里记一笔，绝不自动续锁。
3. **绝不默认改 `DisableTaskMgr` 注册表**。做成"硬核模式"开关，默认关，且开关旁明确写风险。
4. **单实例锁 + 看门狗超时**：钩子回调里不做任何耗时操作（Windows 低级钩子回调超过 `LowLevelHooksTimeout`（默认约 1 秒）会被系统静默移除并导致输入卡顿）。

### 2.2 计时完整性（你现在没考虑，但一定会踩）

用户最省力的绕过方式不是破解，而是**改系统时间**。

- 用**单调计时器**（`QueryUnbiasedInterruptTime` / `GetTickCount64`）作为主时钟；
- 同时记录墙钟时间，两相交叉校验；
- 偏差超过阈值（如 3 分钟）→ 判定为"改时间"或"休眠"，按**较大值**结算剩余时间；
- 关机/休眠：唤醒后按真实流逝时间继续扣减（不能"睡了 2 小时还算在闭关"）；
- 断电重启：可选"欠时补账"机制（这次逃掉多久，下次开始前先补上），比惩罚性弹窗更有威慑力。

### 2.3 安全与分发风险（容易被忽略）

| 风险                 | 说明                                          | 缓解                                    |
| ------------------ | ------------------------------------------- | ------------------------------------- |
| **杀软误报**           | 全局键盘钩子 + 自启动 + 置顶全屏 + 禁用任务管理器，是锁屏勒索软件的教科书特征 | 默认不开注册表修改；开源可自证；上架需 OV/EV 代码签名（每年数千元） |
| **SmartScreen 拦截** | 未签名 exe 首次运行必弹"未知发布者"                       | 签名或开源引导用户"仍要运行"                       |
| **企业/学校环境**        | 组策略/EDR 会直接拦                                | 定位纯个人自用                               |
| **题库版权**           | "导入网上题集"涉及版权                                | 优先 AI 生成 + 用户自建；导入只做格式支持不做内容分发        |
| **家长使用场景**         | 若给孩子装，属"监控软件"，有伦理与隐私问题                      | 需明确定位，别默认往这个方向走                       |

## 三、技术实现路径（可执行）

### 3.1 技术栈建议

| 方案                              | 优点                                                         | 缺点                          | 适配度   |
| ------------------------------- | ---------------------------------------------------------- | --------------------------- | ----- |
| **C# + WPF / WinUI 3 (.NET 8)** | Win32 API 调用最顺、全屏置顶/钩子/服务都是原生、Win11 风格（Mica/亚克力）开箱即用、单文件发布 | 需要 C#                       | ★★★★★ |
| **Tauri 2 (Rust + React)**      | 体积小（~5MB）、前端随心、Win11 风格自己写 CSS                             | 钩子/服务要写 Rust FFI            | ★★★★  |
| **Electron + React**            | 你熟 Node，UI 迭代最快                                            | 体积 100MB+、全屏/钩子要走 native 插件 | ★★★   |
| **Python (PySide6)**            | 你熟 Python，BowToLearn/BreakTimer 都是这个路子                     | 分发差（PyInstaller 易被误报）、性能一般  | ★★★   |

> 若目标是"自己能用的产品"而非"练手"，建议 **C# WPF**；若要快速出 UI 原型，Tauri 也够。

### 3.2 模块拆分（对应说明书里的后期功能）

```
┌─ ui/            设置页、闭关页、题库管理、日志（Win11 风格）
├─ session/       会话状态机 + 计时引擎（单调时钟 + 墙钟校验）
│   Idle → Arming → Locked → Unlocking → Settled → Idle
│                    └─→ (异常) Recovered
├─ lock/          多屏置顶全屏窗口、WM_CLOSE 拦截、光标限制
├─ guard/         低级键盘钩子（可关）、注册表策略（默认关）、看门狗服务（可关）
├─ bank/          题库（本地 SQLite）、随机抽题、答案校验（选择题/填空题/简答模糊匹配）
├─ vault/         退出密钥（随机 token / 自设题答案哈希）
├─ record/        闭关记录、破戒记录、连续天数、境界体系
└─ ipc/           UI ↔ guard ↔ 服务 的本地 IPC（命名管道）
```

**防绕过分级**（做成设置里的"结界强度"，默认 L1）：

| 等级    | 手段                                  | 破解成本          | 权限         |
| ----- | ----------------------------------- | ------------- | ---------- |
| L0 柔和 | 仅置顶全屏窗口，不拦快捷键                       | 10 秒          | 普通         |
| L1 标准 | + 键盘钩子拦 Alt+Tab/Win/Ctrl+Esc/Alt+F4 | 1–2 分钟        | 普通         |
| L2 硬核 | + 注册表禁用任务管理器 + 看门狗服务（被杀自动重启）        | 5–15 分钟（安全模式） | 管理员        |
| L3 内丹 | 独立受限账户 + Shell 替换（登录即进闭关壳）          | 需要另一个管理员账户    | 管理员 + 系统改动 |

> 说明书里的"最高等级"其实就是 L2。**把 L3 写进文档但默认不实现**，因为风险太高（配错了就进不去桌面）。

### 3.3 MVP 边界（建议第一版只做这些）

**做**：设置时长（15min–8h）→ 倒计时确认 → 全屏闭关页（暖白/暗色）→ 实时倒计时 → 退出按钮 → 冷却期 → 抄写/答题 → 解锁 → 结算页 → 本地记录列表。  
**不做**：题库导入、AI 出题、服务看门狗、白名单、境界体系、破境续时（这些留接口，`session.extend()` / `bank.import()` 先留空实现）。

按这个范围，一个熟手 2 周内能出可用版。

### 4.3 调研结论

1. **"桌面端 + 全屏锁 + 计时"不新鲜**，BowToLearn / BreakTimer / Cold Turkey 已经把这条路走完了。
2. **"桌面端 + 题库随机答题解锁"几乎是空白**。搜遍 GitHub，答题解锁只出现在安卓（StudyMust）与安卓数学题（PlugBrain）。这确实是差异化点。
3. **但空白的成因值得警惕**：安卓能做系统级锁屏，Windows 不能；桌面端开发者普遍选择"打字/长文本"这种更简单也更有效的摩擦，说明**题库答题的边际价值可能不够抵消它的实现成本（题库、判题、版权、难度校准）**。
4. **修真叙事（闭关/破境/心魔/道行）是唯一没人做的部分**。这 是你真正的护城河——不是"锁"，是"**把一个痛苦的过程包装成有进度的修行**"。Cold Turkey 只有冷冰冰的倒计时，没有情绪价值。

**差异化定位建议**：`Cold Turkey 的强度（可选） × 题库答题的仪式感 × 修真境界的成长曲线 × Win11 的克制审美`。前两项是功能，后两项才是让人第二天还愿意打开它的原因。

| #  | 问题                                                           | 为什么关键                            | 我的建议默认                                    |

| A1 | **闭关期间到底能不能用电脑？** 纯"离开屏幕"（背单词/纸面题/看书），还是允许白名单程序（网课/PDF/IDE）？ | 决定整个锁屏架构、UI、防绕过等级，是**第一优先级**     | 做**双模式**，MVP 先只做"静修模式"（离开屏幕），研习模式放 V2     |
| A2 | 目标用户是**你自己 + 少数道友**，还是想**做成产品分发/收费**？                        | 决定要不要签名证书、要不要账号体系、要不要外网同步        | 先做自用工具，架构上留分发余地（无账号、纯本地、单文件）              |
| A3 | 主要覆盖哪类学习？**考研/考公/期末冲刺**，还是**长期日常专注**（写代码、写论文）？               | 决定默认时长（4h 闭关 vs 45min 番茄）、决定默认强度 | 备考冲刺为主（长时段 1–4h），日常专注靠后续加番茄节奏             |
| A4 | 要不要"**记录/境界**"这套成长系统？还是只要一个纯粹的工具？                            | 这是留存关键，也是最花时间做的部分                | 必须做，但 MVP 只做"记录列表 + 累计时长 + 连续天数"，境界体系放 V2 |

### B. 退出机制

| #  | 问题                                                                  | 我的建议默认                                          |
| -- | ------------------------------------------------------------------- | ----------------------------------------------- |
| B1 | **冷却期**接受吗？点退出后必须等 N 分钟才能进入验证环节。                                    | 接受，默认 5 分钟，可配 1–10 分钟                           |
| B2 | 三种退出方式你更信哪个：①自设题（你知道答案）②随机题库（你可能答不出）③**程序生成的随机长文本抄写**（一定抄不完但一定能抄完）？ | 组合：③为主 + ②为"仪式感" + ①作为"我知道自己在干什么"的备用            |
| B3 | **自设题的答案要不要能看？** 说明书里 BowToLearn 那套是"屏幕上有原文对照"——那等于没有门槛，只是耗时。       | 不要给对照。答案只在设置时输入，之后连你自己也看不到（存哈希）                 |
| B4 | 允许**紧急例外**吗（身体不适/急事）？走什么通道？                                         | 允许：长按 Esc 8 秒，直接解，但记"破戒（紧急）"，且可选"下次补时"          |
| B5 | **时间到了**是自动解锁，还是弹窗问"要不要退出"？                                         | **自动解锁**。给"到点自由"的确定性，比多一次选择更重要；"继续闭关"做成解锁后的一个按钮 |

### C. 防绕过 / 强度

| #  | 问题                                                | 我的建议默认                        |
| -- | ------------------------------------------------- | ----------------------------- |
| C1 | 需要拦到什么程度？**L1（拦快捷键）就够**，还是要 **L2（禁任务管理器 + 看门狗）**？ | 默认 L1，L2 做成设置开关 + 风险提示        |
| C2 | 用户**改系统时间 / 关机 / 拔电**算不算逃关？要不要"欠时补账"？             | 算，但只记录不惩罚；"补账"作为可选开关          |
| C3 | 能不能接受**杀软误报**（很可能会报）？要不要开源？                       | 默认不开注册表修改以降低误报；开源放在决定做产品之后再议  |
| C4 | 双屏、第二台设备、手机 —— 要不要管？                              | MVP 不管，明确写在"已知局限"里；V2 考虑手机端联动 |

### D. 题库与内容

| #  | 问题                                   | 我的建议默认                                                  |
| -- | ------------------------------------ | ------------------------------------------------------- |
| D1 | 题库从哪来？**自建**（你出）、**AI 生成**、**用户导入**？ | 自建 50–100 题打底（数学/物理/英语/计算机各 20 题）+ 支持 JSON 导入；AI 生成放 V2 |
| D2 | 题型要哪些？选择题最省事，简答题判分是坑                 | MVP 只做**选择题 + 填空题**（精确/去空格匹配）。简答题不做                     |
| D3 | 难度怎么定？"起码大学知识"——但你自己答不出自己的题就没法正常退出   | 分三档（高中/本科/考研），**默认"本科"**，允许设置时自己试做一次校准                  |
| D4 | 每次退出抽几题、答错怎么办？                       | 3 题，全对放行；错 1 题 → 换一组再抽 3 题（不限次数，但每次都要过冷却期）              |

### E. 范围与体验

| #  | 问题                                      | 我的建议默认                                                |
| -- | --------------------------------------- | ----------------------------------------------------- |
| E1 | 闭关页除了倒计时，还要放什么？（说明书只写了壁纸+倒计时，2 小时会非常枯燥） | 大号环形进度 + 已坚持时长 + 一句语录（可切换）+ 可开关白噪音 + "本次目标"一行字（开始前填写） |
| E2 | 语录从修真网文抄吗？**有版权风险**，建议自己写或 AI 生成        | AI 生成 100 条打包，避免直接抄原文                                 |
| E3 | 第一次打开软件，要不要有"新手说明"（讲清楚它锁不死、有哪些逃逸方式）？    | 必须有。**诚实说明边界**能显著降低差评和"这软件差点把我坑死"的事故                  |
| E4 | 要不要开机自启？                                | **默认关闭**，且提供显眼的"关闭自启"入口。这是防"变砖"的关键                    |

## 六、如果现在开工，我建议的顺序

1. **先定 A1、A2、B4、B5 四个答案**（其余可以边做边定）。这四个决定架构。
2. **第 1 周**：会话状态机 + 计时引擎 + 置顶全屏窗口（单屏）+ 崩溃自恢复 + 逃生通道。做到"能锁能解不锁死"。
3. **第 2 周**：设置页 + 闭关页 UI（暖白/暗色）+ 结算页 + 本地记录（SQLite）。
4. **第 3 周**：冷却期 + 抄写验证 + 题库模块 + 抽题判分。
5. **第 4 周**：L2 硬核模式（钩子 + 可选看门狗）、多屏、DPI 适配、语录/白噪音。
6. **之后**：境界体系、破境续时、题库导入、AI 出题。

> 建议在第 2 周末就自己真实使用 3 天。**你会发现真正的问题不在防绕过，而在"闭关 2 小时里界面太无聊，你会想尽办法找事做"**。这一步的反馈价值高于再多写一周代码。
