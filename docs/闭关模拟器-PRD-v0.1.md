## 1. 产品概述

### 1.1 一句话定位

> 一个本地运行的 Windows 桌面工具：**用户自愿把自己锁在电脑之外**，用全屏结界、冷却期与问阵构成退出成本，把"我想学习"的意志力承诺变成"电脑替我执行"的物理限制。

### 1.2 背景与问题

目标用户（"道友"）的真实困境不是不懂方法，而是**学习前下意识打开电脑**，一玩就不可收拾。番茄钟、待办、Forest 这类正向激励工具**不解决"手已经放上键盘"那 3 秒**。

### 1.3 目标用户

| 维度 | 描述 |
|---|---|
| 主要用户 | 开发者本人 + 少数道友（≤10 人，自行分发 zip） |
| 典型场景 | 考研/考公/期末冲刺；线下纸质学习（背书、刷题、看教材）；需要连续 1–4 小时不看屏幕 |
| 非目标用户 | 需要边用电脑边学习者（网课/写代码）→ v0.3 研习模式；家长远程管控孩子 → 不做 |

### 1.4 v0.1 明确不做的事（防蔓延）

| 不做 | 原因 |
|---|---|
| 研习模式（应用白名单） | 架构差异大，v0.3 再做 |
| 番茄循环（学 25 休 5） | 休息即解锁，与"静修"目标冲突 |
| 账号 / 云同步 / 排行 | 纯本地，无服务器 |
| 开机自启 / 常驻服务 / 看门狗 | 防变砖 + 降低杀软误报（L1 的代价，见 §13） |
| 自动更新 | 需签名与服务器；改为手动 git |
| 境界/道行体系 | v0.2 |
| 家长管控 / 多用户 | 定位不符，涉及伦理 |

### 1.5 成功标准

v0.1 成功的唯一标准：**作者本人连续使用 14 天，其中 ≥10 天完成 2 小时以上闭关，且没有一次因软件故障被锁死或丢数据。**

## 2. 设计原则（冲突时的裁决顺序）

1. **绝不锁死**：任何异常路径都必须通向"可以出关"。宁可被绕过，不可变砖。
2. **摩擦优先于难度**：冷却时间比题目难度更有效。题目是仪式，冷却才是墙。
3. **诚实**：不谎称"无法退出"。首次运行即告知全部逃逸路径与已知局限。
4. **仪式感是留存**：界面语言、长老叙事、钟鸣、阵法——这些不产生功能价值，但决定第二天还愿不愿意打开。
5. **零侵入系统**：不写注册表、不自启、不注入进程、不联网。用户的系统必须是干净的。

## 4. 核心流程

### 4.1 首次使用

```
启动 → 首次引导（3 屏）
      ├─ 屏 1：这是什么 / 它锁不死什么（诚实声明，含全部逃逸路径）
      ├─ 屏 2：加固建议（关闭三指/四指手势 · 检查系统熄屏时间 · 音量建议）
      └─ 屏 3：一句话介绍术语（道友 / 长老 / 阵法 / 出关）
   → 主界面（配置）
```

### 4.2 一次完整闭关

```
配置（时长/阵法/目标）→ 点击「入关」
  → Arming：3-2-1 全屏接管，末帧提示"可长按 Esc 8 秒破戒"
  → Locked：倒计时、环形进度、长老对话
      ├─ 到点 ────────────────→ Settled(completed) → 钟鸣 → 结算页
      ├─ 点「解开阵法」→ Cool → Challenge ─┬─ 全对且 n<3 → Settled(early)
      │                          ↑ 答错     ├─ 全对且 n≥3 → Copying → 抄写通过 → Settled(early)
      │                          └──────────┘ 回 Cool（成本+1，不公布答案）
      ├─ 长按 Esc 8s → 二次确认（9 字）→ Settled(emergency，记一过)
      ├─ 显示配置变化 → Settled(accident，记一过)
      └─ 进程消失 → 下次启动 Recovered（自动解锁，记 interrupted）

  ※ 全局规则：任何状态下剩余时间归零，一律直接进 Settled(completed)。
  ※ 剩余时间不足一次冷却时，「解开阵法」不进入 Cool，只提示"请稍候到点"。
```

## 5. 状态机规格

### 5.1 状态定义

| 状态 | 界面 | 可输入 | 退出方式 |
|---|---|---|---|
| `Idle` | 配置页 | 全部 | — |
| `Arming` | 全屏黑底 + 3-2-1 | 无（Esc 取消，3 秒内） | 自动进入 Locked |
| `Locked` | 闭关页 | 「解开阵法」/ 长按 Esc | 到点 / 答题 / 紧急 / 显示变化 |
| `Cool` | 闭关页（对话替换为冷却语） | 无（**不可跳过、不可关闭**） | 计时结束 → Challenge |
| `Challenge` | 闭关页（对话区变题目） | 选项点击 1–4 | 全对 / 答错 |
| `Copying` | 闭关页（对话区变抄写区） | 逐字抄写输入（可退格） | 校验通过 |
| `Confirming` | 紧急确认遮罩 | 抄写输入 | 确认 / 取消（取消回 Locked，成本不变） |
| `Settled` | 结算页 | 「再来一关」/ 关闭 | — |
| `Recovered` | 提示弹窗 | 关闭 | → Idle |

### 5.2 转移表

| 当前 | 事件 | 下一 | 副作用 |
|---|---|---|---|
| Idle | 点击「入关」 | Arming | 记录 `startedAtMs`；置顶全屏；开启拦截；锁定电源状态；压暗 |
| Arming | 3 秒结束 | Locked | 开始计时；`session.json` 首写 |
| Arming | Esc（短按） | Idle | 撤销全部系统改动 |
| Locked | 点「解开阵法」 | Cool | 校验剩余时间（不足一次冷却则拒绝，见 F-4.5）；`attempts += 1`；计算 cooldown/题数 |
| Locked | 剩余 ≤ 0 | Settled | `result=completed`；钟鸣；撤销拦截 |
| Locked | 长按 Esc 8s | Confirming | — |
| Locked | 显示配置变化 | Settled | `result=accident`；`faults += 1`；撤销拦截 |
| Cool | **冷却计时结束** | Challenge | 抽题（按记忆衰减与退化规则，见 F-8.2） |
| Challenge | 全对且 `n < 3` | Settled | `result=early`；钟鸣 |
| Challenge | 全对且 `n ≥ 3` | Copying | 下发本次抄写文本（100 / 200 字，见 F-5.8） |
| Copying | 逐字校验通过 | Settled | `result=early`；钟鸣 |
| Challenge | 任一错误 | Cool | 长老训话（**不公布正确答案**）；`attempts += 1`（成本递增） |
| Confirming | 抄写正确 + 确认 | Settled | `result=emergency`；`faults += 1` |
| Confirming | 取消 | Locked | 不消耗成本 |
| 任意（进程死） | 下次启动 | Recovered | 自动解锁；`result=interrupted` |

**到点优先级（全局规则，优先级高于本表所有分支）**

任意状态（`Cool` / `Challenge` / `Copying` / `Confirming`）下 `remaining ≤ 0` → 立即 `Settled(completed)` 并执行 `teardown()`。`attempts` 原样记录、`faults` 不加。理由是原则 1（绝不锁死）与 F-7.1（到点即解放）；否则"剩余时间少于一次冷却"时状态机会卡在冷却或答题里出不来。

**不变量**
- `Cool`、`Challenge`、`Copying`、`Confirming` 期间，剩余闭关时间**照常扣减**（冷却本身就在消耗你的闭关时长，这是设计意图）。
- 任何离开 `Locked` 的路径都必须执行完整的 `teardown()`（还原拦截、电源、亮度、隐藏窗口）。
- `session.json` 在 `Locked` 期间每 15 秒覆写一次。
- `Copying` 期间 Esc / Alt+F4 / Alt+Tab 一律无效（抄写只能用退格与「已抄完」按钮）。

| ID | 需求 | 细则 |
|---|---|---|
| F-3.14 | 主时钟 | 单调计时器（不受系统时间调整影响） |
| F-3.15 | 主时钟与校验 | 以**单调计时**为唯一结算依据：`elapsed = 单调增量 + 睡眠累计`。墙钟只用于两件事——计算睡眠时长、检测时间篡改。墙钟与 `elapsed` 偏差 > 3 分钟且无睡眠事件时，判定为"时间被改动"，**仅在界面显示「不一致」，不影响剩余时间**（用户既不得利也不吃亏） |
| F-3.16 | 休眠处理 | 通过系统电源通知（挂起 / 恢复）**单独累计**睡眠时长：恢复时 `sleepAccum += 墙钟差`。睡 2 小时即扣减 2 小时。不得用"墙钟比单调多走"直接判定睡眠——那会与"改系统时间"混淆 |
| F-3.17 | 时间显示 | `HH:MM`（≥1 小时）或 `MM:SS`（<1 小时），**纯数字倒计时，不显示百分比、不显示进度环角度数值** |
| F-3.18 | 校验时钟 | 右下角 11 px 灰字：`系统 21:03 · 一致`；不一致时红色 `不一致 (+12 分)` |
| F-3.19 | 精度 | 8 小时内误差 ≤ 1 秒 |

#### 6.3.4 显示配置变化

| ID | 需求 | 细则 |
|---|---|---|
| F-3.20 | 检测方式 | **不使用** `WM_DISPLAYCHANGE`（无窗口线程收不到该消息，且熄屏唤醒会误报）；改为**每 1 秒轮询显示器快照** |
| F-3.21 | 去抖与判定 | 快照 = 显示器数量 + 各屏分辨率 + 各屏 DPI（按坐标排序后比对）；**连续 2 次（≈2 秒）不一致**才判定成立；任一次回到基线即计数清零 |
| F-3.22 | 处理 | 判定成立 → 立即 `teardown()` → 出关 → `result=accident`、`faults += 1` → 弹窗：「检测到显示配置变化（拔屏/改缩放），已为你出关。本次记为一次过。」 |
| F-3.23 | 不得误判 | 熄屏唤醒、DPI 未变的窗口重建、显卡驱动瞬时重置**不得**触发出关 |

### 6.4 冷却（Cool）

| ID | 需求 | 细则 |
|---|---|---|
| F-4.1 | 时长 | `cooldown(n) = min(5 + 5 × (n - 1), 20)` 分钟，n = 本次闭关第 n 次尝试 |
| F-4.2 | 不可跳过 | 无"跳过""返回"按钮；不可通过任何界面操作缩短 |
| F-4.3 | 界面 | 对话框显示："**正在通知长老，请稍候。**" + 一行小字"还剩 4 分钟"（**分钟粒度，不显示秒**）+ 当前已坚持时长 |
| F-4.4 | 文案轮换 | 冷却期间每 30 秒换一句长老语（取自该阶段语料），但**不显示可关闭的倒计时进度条**（避免盯进度） |
| F-4.5 | 剩余不足时拒绝 | 若 `remaining < cooldown(n)`（含第 1 次的 5 分钟），点「解开阵法」不进入 Cool，改为在对话框提示："距出关不足一次冷却，请稍候到点。"并保持 `Locked`。理由：否则用户等完冷却才发现闭关已到点，体验上是"白等"，状态机上也必然撞上全局到点规则 |

### 6.5 问阵（Challenge）

| ID | 需求 | 细则 |
|---|---|---|
| F-5.1 | 题型 | v0.1 **仅选择题**（4 选 1）。填空题 v0.2 |
| F-5.2 | 题数 | `questions(n) = min(3 + (n - 1), 5)`；基准题数可设 3–5（F-10.5），**不得低于 3**（2 题蒙对率 6.25%，会让"蒙不过去"的论证失效） |
| F-5.3 | 抽题 | 从当前阵法随机抽，遵守记忆衰减（F-8.2）；同一轮内不重复 |
| F-5.4 | 选项打乱 | 每次展示前打乱选项顺序。**打乱在 Rust 侧完成并持有"展示索引 → 原始索引"映射**，前端只回传展示索引，不持有答案 |
| F-5.5 | 判定 | **全部答对才放行**；只要错 1 题即失败（剩余题不再作答，直接进训话）。**答错时不公布正确答案**，任何响应体不得含 `answer` |
| F-5.6 | 答题界面 | 对话框内：题干（最多 3 行）+ 4 个选项（键盘 1–4 / 鼠标点击）；**不做 Enter 快捷提交**，避免连按误选 |
| F-5.7 | 答错处理 | 长老训话（引用该阶段语料，可给知识点关键词，不给答案）→ 显示"本次需再等 {cooldown} 分钟、答 {n} 题" → 回 Cool，`attempts += 1` |
| F-5.8 | 抄写（第 3 次起） | n ≥ 3 时全对后进入 `Copying`：n=3 抄 100 字，n ≥ 4 抄 200 字。**文本来源**：`quotes.json` 的 `copy` 段按阶段抽取，**全程显示原文对照**，逐字校验（错字标红，可退格），下方「已抄完」按钮提交。**抄写文本只含中文字符与中文标点**，不得含英文、数字、半角标点（避免全角半角与输入法造成的无效挫败）。Esc / Alt+F4 在抄写期间无效 |
| F-5.9 | 蒙对概率 | 3 题全对 = 1/64 ≈ 1.6%，可接受；**不因此提高题目难度** |
| F-5.10 | 不泄题 | `list_questions`、`question://changed`、`submit_choice` 的返回体**一律不含 `answer`**；答错的题同样进入 30 分钟冷却（见 F-8.2），避免"错一题 = 知道答案" |

### 6.6 紧急破戒（Confirming）

| ID | 需求 | 细则 |
|---|---|---|
| F-6.1 | 触发 | Locked 状态下长按 Esc 满 8 秒（屏幕中央显示进度环 + "破戒需谨慎"）。**长按判定在 Rust 钩子线程按 Esc 按下/抬起时间戳完成**，前端只渲染进度、不参与判定；进入 `Locked` 时清零按键状态，`Arming` 期间按住的 Esc 不计入 |

| F-6.3 | 代价公示 | 输入框上方显示：本次 {elapsed} 将不计入累计 · 今日将不计为有效日 · 破戒累计 {faults} 次 |

| ID | 需求 | 细则 |
|---|---|---|
| F-8.1 | 种子题库 | v0.1 内置「基础阵法」**30 题**：数学 10 / 英语 10 / 计算机 10，本科难度，全部 4 选 1（rev4 由 60 题下调，见 M5 计划 D-38；因此 A-16 的"总数 < 30 出黄字"不再自然触发，验它要手工把题库删到 29 题） |

## 7. 退出成本模型

| 尝试次数 n | 冷却 | 题数 | 额外 |
|---|---|---|---|
| 1 | 5 分钟 | 3 | — |
| 2 | 10 分钟 | 4 | — |
| 3 | 15 分钟 | 5 | 抄写 100 字 |
| ≥4 | 20 分钟（封顶） | 5 | 抄写 200 字 |

```
cooldown(n)  = min(base + step × (n-1), 20)        base=5, step=5
questions(n) = min(qbase + (n-1), 5)                qbase=3
copyChars(n) = n >= 4 ? 200 : (n == 3 ? 100 : 0)
```

**关键约束：`attempts` 在本次闭关内单调递增，答错不清零，冷却结束不重置。**（这是与初版设计最重要的差异——初版"答错重抽"会让成本归零，等于无限试错。）

**首次尝试的时间成本已有 5 分钟**：即使用户一次答对，也已经付出 5 分钟。5 分钟是冲动衰减的临界点，这是整个防线的核心，而不是题目。

**与剩余时间的边界**：若 `remaining < cooldown(n)`，`Locked` 阶段就直接拒绝进入冷却（F-4.5），不会出现"等完冷却发现已经到点"的空转；若冷却中途到点，由 §5.2 的全局到点规则接管，直接结算为 `completed`。

## 8. 数据模型

```jsonc
// bank/seed.json
{
  "version": 1,
  "id": "basic",
  "name": "基础阵法",
  "questions": [
    {
      "id": "q001",
      "type": "choice",
      "difficulty": "undergrad",
      "tags": ["math"],
      "source": "generated",
      "stem": "∫₀¹ x² dx 的值是？",
      "options": ["1/4", "1/3", "1/2", "1"],
      "answer": 1,
      "hint": "幂函数积分公式"
    }
  ]
}

// bank/stats.json  ← 记忆衰减用（答对、答错都写 lastAskedMs，见 F-8.2）
{ "q001": { "lastAskedMs": 1760875920000, "rightCount": 2, "wrongCount": 0 } }

// config.json  ← 设置 + 少量跨会话状态
{
  "version": 1,
  "dim": true,
  "physicalBrightness": true,
  "chimeVolume": 0.6,
  "cooldownBase": 5,
  "questionBase": 3,
  "theme": "dark",
  "lastDurationMin": 120,
  "recentQuotes": ["道友，且坐。"]   // 最近 5 条已用评语，防重复（F-7.7 / T-8）
}

// records.jsonl（一行一条，只追加）
{"id":"s_1760875920000","startedAtMs":1760875920000,"endedAtMs":1760883120000,
 "plannedMs":7200000,"actualMs":7200000,"result":"completed","attempts":0,"faults":0,"bank":"basic"}

// session.json（Locked 期间每 15s 覆写；正常出关时删除）
{"state":"Locked","targetMs":7200000,"elapsedMs":1830000,
 "monoBase":123456789,"wallBaseMs":1760875920000,"startedAtMs":1760875920000,
 "attempts":1,"cooldownUntilMs":null,"bank":"basic","goal":"背完 List 5–7"}
```

**时间戳口径（v0.1-rev3 起）**：所有时间戳一律存 **Unix 毫秒**（UTC，`i64`，字段名带 `*Ms` 后缀），**不存 ISO 8601 字符串**。理由：免时区/夏令时换算、免引入时间库、跨午夜归属只做一次整数比较；显示与"有效日"归属在渲染层/统计层按系统时区换算（Win32 `SystemTimeToTzSpecificLocalTime`），存储里不写时区。`monoBase` 仍是单调时钟原始刻度，不是毫秒时间戳，不要混用。详见 `docs/decisions/003-时间戳存储格式.md`。

**写入策略**：`records.jsonl` 追加写，永不重写；`session.json` 原子写（写临时文件 → rename），避免崩溃时半截文件。

## 12. 错误与异常处理

| 场景 | 处理 |
|---|---|
| 进程崩溃 / 被杀 | 下次启动检测到残留 `session.json` → `Recovered` 弹窗："上次闭关异常中断，已自动解除。本次时长照常计入累计，但不计为有效日。" → 记 `interrupted`（`actualMs` 取快照中的 `elapsedMs`，见 TDD §4.8）→ 删除 session 文件 |
| 全屏窗口创建失败（某块屏） | 降级为覆盖主屏 + 记录警告；若主屏也失败 → 拒绝入关并提示 |
| 钩子安装失败 | 拒绝入关，提示"结界未能生效，请以普通用户重试或检查安全软件拦截"（**不允许"无钩子也进闭关"**，否则用户以为锁了其实没锁） |
| 亮度还原失败 | 记日志；设置页"恢复默认亮度"手动兜底 |
| 题库解析失败 | 回退内嵌题库；若内嵌也失败 → 禁止入关并提示（不能出现"无题可问"的闭关） |
| 记忆衰减导致可抽数为 0 | 按 F-8.2 的两级退化回退（冷却池 → 最久未出现优先）；题库被删到 < 3 题 → **拒绝入关**并提示，绝不出 2 题的轮次（蒙对率会从 1/64 跳到 1/16） |
| 记录文件损坏 | 跳过损坏行继续解析；界面提示"部分记录损坏，已跳过 N 条" |
| 系统时间被大幅回拨 | 不中断闭关；取单调值为准；校验时钟显示"不一致" |
| 用户在闭关中切换用户（Win+L 后换账号） | 无法阻止；原会话继续计时，回来仍在 Locked |

## 13. 已知局限（必须在"关于"页完整展示；措辞可收敛，事实不得删）

1. **`Ctrl+Alt+Del` 拦不住。** 按下去会出现系统安全界面，你可以从那里进任务管理器结束本程序。这是 Windows 的安全设计，任何用户态程序都无法拦截。
2. **触控板三指/四指手势拦不住。** 那是系统手势不是键盘事件。建议在系统设置里关掉。
3. **安全模式、拔电源、长按电源键、用另一个管理员账户登录，都拦不住。**
4. **本软件不联网、不做完整性校验，本质上是"防手滑"而不是"防黑客"。** 它挡的是你 3 秒钟的冲动，不是你 30 分钟的钻研。
5. **v0.1 不防多设备。** 手机上还能刷，另一台电脑也一样。
6. **闭关时屏幕会黑，这是正常现象**，按任意键唤醒即可看到倒计时，计时不受影响。
7. **题库与统计文件是明文的。** 你可以打开 `%APPDATA%\闭关模拟器\bank\seed.json` 看到全部答案并直接修改；删掉 `bank\stats.json` 就能把记忆衰减重置。本软件不做完整性校验——它挡的是你 3 秒钟的冲动，不挡你花 10 分钟做技术准备。知道这一点仍愿意用它，才是它开始起作用的时刻。
8. **任务栏右键可能仍能打开任务管理器。** v0.1 不锁鼠标、不隐藏任务栏，靠置顶窗口覆盖整块屏幕来压制它；在混合 DPI、多屏或某些显卡驱动下覆盖可能失败，此时这条路径等同于 `Ctrl+Alt+Del`，拦不住。
9. **`Win` 键与 `Win` 组合键仍可能唤出开始菜单或桌面。** 本程序会用置顶与抢焦点在 1 秒内收回，但这一瞬间桌面可能闪出。请勿把它当作"能防住自己"的依据。（2026-10-20 真实键盘复验，见 `decisions/006`）

## 14. 关键设计决策说明

| # | 决策 | 理由 |
|---|---|---|
| D-1 | 不做本地前后端分离 | 本地 HTTP 端口会让"解锁"变成可被任意本机进程/网页 JS 调用的接口，防绕过形同虚设。改为进程内分层 + IPC。 |
| D-2 | 冷却期是主防线，题目是仪式 | 冲动持续 30 秒–3 分钟，5 分钟冷却的拦截率远高于任何难度的题；且题目可被搜索/记忆。 |
| D-3 | `attempts` 单调递增、不清零 | 初版"答错重抽"等于无限试错，题库再大也终会蒙对。 |
| D-4 | **破戒不清零连续天数，改为"当日不计有效日"** | 保留"断签"的真实代价，但不抹掉两周历史——清零会直接导致卸载。这是对初版方案的修正。 |
| D-5 | 允许熄屏、阻止睡眠 | 静修模式下用户必然离开电脑；不阻止睡眠会让钩子随睡眠挂起，锁失效。允许熄屏可省电、防 OLED 烧屏、减少诱惑。 |
| D-6 | 显示配置变化直接出关（记一过） | 无法可靠重建多屏布局，重建失败就是锁死。宁可让用户逃脱一次。 |
| D-7 | 钩子安装失败则拒绝入关 | 绝不允许"看起来锁了其实没锁"，那是最坏的用户体验。 |
| D-8 | 不做开机自启 | 防变砖 + 降低杀软误报。 |
| D-9 | 崩溃不续锁 | 崩溃后自动续锁会让人打不开自己的电脑，是产品级的致命事故。 |
| D-10 | 计时 = 单调增量 + 睡眠事件累计 | 「取单调值与墙钟的较大值」会把调快系统时间的收益送给用户，与 A-9 直接冲突；睡眠与改时间在数值上同形，只能靠独立的电源事件区分。（v0.1-rev1 修订） |
| D-11 | 显示变化用轮询快照而非窗口消息 | `WM_DISPLAYCHANGE` 在无窗口线程收不到，且熄屏唤醒会误报；1 秒轮询 + 连续 2 次确认同时满足去抖与 2 秒响应。（v0.1-rev1 修订） |
| D-12 | 到点是最高优先级，且剩余不足一次冷却时拒绝解锁 | 冷却与闭关时长会重叠，若不给"到点"绝对优先，"剩余 3 分钟点解开"必然卡在冷却里；反过来若允许进入，用户是白等。两条合起来让边界只有一种结果：到点就走。（v0.1-rev2 修订） |
| D-13 | `accident` / `interrupted` 计入累计但不计有效日 | 崩溃与拔屏的时长是真实发生的，全作废等于让用户替软件的故障买单，会直接导致卸载；但不计有效日、照记一过，代价仍在。（v0.1-rev2 修订） |

## 15. 验收标准

| # | 用例 | 通过条件 |
|---|---|---|
| A-1 | 设 25 分钟入关 | 3 秒内全屏接管；25 分钟到点自动解锁并响铃 |
| A-2 | 多屏 | 每块屏均被覆盖，快捷键在任何屏上都无效 |
| A-3 | 拦键 | Alt+Tab / Ctrl+Esc / Ctrl+Shift+Esc / Alt+F4 / F11 全部无效；音量键有效。**`Win` 相关组合键不在保证范围内**（见 §13-9，`Win+D` 只保证 1 秒内收回） |
| A-4 | 冷却 | 剩余 ≥ 5 分钟时第 1 次点「解开」必须等 5 分钟（±2 秒），期间无任何跳过入口；剩余 < 5 分钟时被拒绝进入冷却 |
| A-5 | 成本递增 | 连错 3 次，冷却为 5→10→15 分，题数 3→4→5，且第 3 次出现抄写 |
| A-6 | 蒙题 | 只有全对才放行；错 1 题即回冷却 |
| A-7 | 紧急 | 长按 Esc 不满 8 秒松开 → 无事发生，进度归零 |
| A-8 | 紧急 | 长按 8 秒 + 抄写正确 → 出关，记录 `emergency`，破戒 +1 |
| A-9 | 改时间 | 闭关中把系统时间调快 1 小时 → 剩余时间不变；校验时钟显示"不一致" |
| A-10 | 睡眠 | 闭关中合盖休眠 10 分钟再唤醒 → 剩余时间减少约 10 分钟，仍在锁屏 |
| A-11 | 杀进程 | 任务管理器结束进程 → 锁消失；重启程序 → 不自动续锁，弹出 `Recovered`，记录 `interrupted` |
| A-12 | 拔外接屏 | 2 秒内自动出关（实现：1 秒轮询 × 连续 2 次不一致），记 `accident`，破戒 +1 |
| A-13 | 熄屏 | 闭关中静置 15 分钟 → 屏幕熄灭；按键唤醒 → 仍在闭关，倒计时正确 |
| A-14 | 亮度 | 入关后内置屏亮度降低；出关后恢复原值（误差 ≤ 5%） |
| A-15 | 记忆衰减 | 某题答对后 30 天内不再被抽中；某题答错后 30 分钟内不再被抽中 |
| A-16 | 题数提示 | 题库总数 < 30 时，配置页与闭关页均出现黄字"阵法简陋"；题库总数 ≥ 30 时即使可抽数很少也不出该黄字，只显示"可抽 X 题" |
| A-17 | 连续天数 | 连续两天各闭关 30 分钟 → 连续 2 天；第三天只闭关 10 分钟 → 仍显示 2 天（当日未断签，未达标） |
| A-18 | 断签 | 第四天不闭关 → 第五天打开时显示 0（已断签）；第五天再闭关 30 分钟后 → 显示 1 |
| A-19 | 长稳 | 连续 8 小时闭关，内存增长 ≤ 30 MB，无崩溃 |
| A-20 | 离线 | 断网状态下全部功能可用 |
| A-21 | 到点优先：剩余 6 分钟点「解开」→ 冷却 5 分钟 → 答错 → 冷却 10 分钟期间剩余到 0 | 自动进入结算（`completed`），不卡在冷却或答题里；`attempts` 如实记录 |
| A-22 | 剩余不足：剩余 3 分钟点「解开阵法」 | 不进入冷却，对话框提示"距出关不足一次冷却，请稍候到点"，仍在 `Locked` |
| A-23 | 抄写：第 3 次尝试全对 | 进入抄写区，需抄满 100 字逐字通过才出关；错字标红可退格；抄写中 Esc / Alt+F4 无效 |
